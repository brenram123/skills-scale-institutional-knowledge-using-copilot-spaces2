# OctoAcme Project Management Docs

OctoAcme’s project management approach is **customer-first, iterative, and data-informed**, with clear ownership and psychological safety. Projects move from initiation and planning through execution, release, and retrospective. These guides provide practical workflows, checklists, templates, and role guidance for consistent project delivery.

## Process Overview

Projects begin with a project one-pager that validates the problem, goal, measurable success criteria, stakeholders, timeline, resources, and initial risks. Planning converts approved work into a prioritized backlog with estimates, acceptance criteria, a Definition of Done, dependencies, a release timeline, and milestone map.

Delivery teams use a project board and short feedback loops to move work from Backlog to Ready, In Progress, In Review, QA, and Done. Pull requests should be small, include issue links and acceptance criteria, pass automated tests and linting, and receive the required review approval. Quality is built into execution through unit, integration, end-to-end, security, and manual testing as appropriate. Risks and dependencies are maintained in a register, reviewed regularly, and escalated from team triage through the PM and Product Lead to sponsors when needed.

Clear role ownership supports effective communication: Project Managers coordinate delivery, schedules, risks, and stakeholder updates; Product Managers define outcomes and priorities; Developers implement and test features; QA validates quality; and stakeholders provide decisions and approvals. The team communicates through standups, PM–Product alignment, planning and review meetings, demos, weekly status updates, and retrospectives. Releases include pre-release checks, staging smoke tests, production verification, rollback readiness, and stakeholder communication. Retrospectives turn learnings into owned, dated backlog actions that continuously improve future work.
